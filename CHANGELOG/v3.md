# v3 Changelog

## [v3.1.0]

First release of the Microsoft365DSC fork. Rebased onto the upstream v2.0.7 pure-script lineage.

### Main changes

- Renamed to `M365DSC.PSDesiredStateConfiguration` so the package no longer collides with the
  Microsoft-owned `PSDesiredStateConfiguration` module. The package additionally contains a small
  compatibility module of the same version that keeps the legacy name. The engine resolves the module
  named `PSDesiredStateConfiguration` while it executes a configuration statement, and that module owns
  the qualified `PSDesiredStateConfiguration\Configuration` call every compiled configuration body
  makes. The folder holding both modules must be on `PSModulePath`.
- Rebased onto the upstream v2.0.7 pure-script lineage. The net6 DscSubsystem binary was removed;
  the module is plain PowerShell script and the build is a plain copy of the source tree
  (`build.ps1` / `dobuild.ps1` with PSPackageProject).
- Dual-edition support: the same module runs on Windows PowerShell 5.1 (Desktop) and PowerShell 7 (Core).
- Deterministic MOF output: `Author`, `GenerationDate`, and `GenerationHost` stamps are no longer
  emitted, line endings are LF, and files are written as UTF-8 without BOM on both editions
  (Windows PowerShell 5.1 previously produced UTF-16 through output redirection).
- Retained upstream MOF emission fixes: resource properties with an empty array value are included
  in the MOF (#127), and array parameters in key-value pairs are emitted correctly (#128).
- Keyword cache retention across compiles: repeated same-session compiles of Microsoft365DSC
  configurations drop from 38-41 s to 2-4.5 s.
- Behavior change: multi-version import dedupe. When several versions of a resource module are
  installed, `Import-DscResource` now imports only the highest (or the explicitly requested) version
  instead of every installed version.
- Removed the `Get-PSCallStack` call from the per-resource driver function (performance).
- Behavior change: conflict detection bucketing. Duplicate-key detection now compares only resources
  whose key-property values collide, instead of comparing every resource pair.
- New fast compilation host: `Invoke-DscFastCompile` plus the schema cache commands
  `Export-DscSchemaCache`, `Test-DscSchemaCache`, and `Clear-DscKeywordCache`. Compiles
  Microsoft365DSC (>530 class-based resources) configurations in 7-20 s in a fresh process and
  2-7 s on repeat, against a 67-96 s baseline, using a persistent JSON schema cache.
  Script-based (`*.schema.mof`) and composite (`*.schema.psm1`) resources automatically fall back to
  the standard compilation path. See `docs/FastHostContract.md`.
- Behavior note: in the fast host, `Test-MofInstanceText` validation is skipped unless `-ValidateMof`
  is specified.
